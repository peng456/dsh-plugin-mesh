# S · 安全 子路线图

> 父文档：[`ROADMAP.md`](../../ROADMAP.md) §2 · **唯一不被任何方向闸住的方向**：可以立刻开始。
> 背景：[`../../SECURITY.md`](../../SECURITY.md) · [`../DESIGN-NOTES.md`](../DESIGN-NOTES.md)（安全模型节）

**回答什么**：陌生设备能不能让我执行东西？危险动作有没有人点头？事后能不能查？

**默认姿态（决策 Q3，不重开）**：**零配置，装上就能派普通任务。** 这是产品选择，不是遗漏。
代价：同网段匿名可派 —— 这条必须写在 README 安全节，让使用者知道边界在哪。

## 现状（v0）

| 已有 | 缺 |
|---|---|
| `pairing.js` 配对码（两端同码，不一致 403） | 默认关闭（`requirePairing: false`） |
| `web-fence.js` 反代边界 | 无审计、无按对端策略 |
| 面板「一键关闭」局域网 / 互联网 | 幽灵对端不校验：自报 `app:"dsh-mesh"` 就能混进对端表 |
| 对端任务默认 `workspace-write` 权限 | 危险命令无确认 |

**已发生的两件事**

1. opencode 起的服务自报 `proto:"opencode-mesh"` 却自称 `app:"dsh-mesh"`，成功混进对端表 —— **自报字段不可信**。
2. 一个互回执线程 2.5 小时开了 54 个会话、约 800 万 token —— 循环闸有，但账没记。

## S-v1 · 拦得住（与 R-v1 并行）

| 工作项 | 做法 | 验收 |
|---|---|---|
| 幽灵对端校验 | 宽容版三行校验（`v` / `proto` / id 形态，**字段缺失即放行**），`mesh_run` 解析后再复检一次 | 不再能派到冒名者；拦截计数 ≠ 0 且无静默放行 |
| 高危动作接收方确认 | 删除 / 写系统目录 / 权限变更走接收方 `ask`，一次授权可记住 | 正常派发手感不变；危险动作有人点头 |

**为什么是「宽容版」**：按 `AGENTS.md` 硬约束——**探测失败不能看起来像否定事实**。
旧对端缺字段是「不知道」，不是「不安全」，所以缺字段放行而不是拒绝。

## S-v2 · 查得到

| 工作项 | 做到什么 |
|---|---|
| 审计账 | 能回答「谁在什么时候让谁做了什么、结果如何」；落任务流水账（journal），与 R-v1 同源 |
| 每对端策略 | `allow` / `ask` / `deny`（**默认 allow**，保持零配置） |
| 动作级审批队列 | 危险动作可以排队等人，而不是阻塞整个派发 |

**验收**：任意一条历史任务可追溯到来源机器 + 动作 + 结果；被 `deny` 的对端有明确回执，不是静默超时。

## S-v3 · 边界清楚

| 工作项 | 做到什么 |
|---|---|
| 凭据边界 | MCP HTTP token、tailnet sidecar 目录、配对码（**明文 HTTP 头**，挡误连不挡嗅探）三处各自的明文/权限约束写清楚 |
| 网络类型提示 | 检测到公共 / 企业 Wi-Fi 时提示「此网络可发现你，可开配对码」（不强制） |
| 残余风险文档化 | README 安全节明确「默认允许同网段匿名派发普通任务」是选择而非漏洞 |

## 闸门

**入**：无。
**出**：S-v1 的审计字段被 R-v1 的 journal 承载（同源，不重复造）；无方向等 S。

## 边界

- 不做账号体系（没有中心，也就没有账号）
- 不做 TOFU（决策 Q3 已否）
- 不用「默认 deny」换取安全感 —— 那会毁掉零配置这个核心价值
