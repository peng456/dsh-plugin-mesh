# U · 界面 子路线图（易用性）

> 父文档：[`ROADMAP.md`](../../ROADMAP.md) §2 · v1 被 [`R-v1`](./route.md) 闸住。
> 现状界面：`client/client.js`（手写 bundle，无打包器）

**回答什么**：装上之后多久能出第一个结果？第二次还愿意用吗？

**「可玩」的定义是三个数字，不是视觉工作**：
首次上手 ≤5 分钟 · 7 天内第二次派发 · 每周「围观」次数。
明确不追求：日活、时长、社交裂变。**Mesh 的对手是「人自己手动 SSH」，不是别的 App。**

---

## 现状（v0）

| 已有 | 缺 |
|---|---|
| 侧栏 Mesh 面板、设备卡片、任务列表 | **结果卡**（结果只是一段文本） |
| 手机端适配、卡片工作台 | **完成通知**（只能盯面板） |
| 对端 Web 投屏、SSH 终端 | **`mesh demo`**（无脚本化闭环） |
| 一键关闭、配对码入口 | **驾驶舱**（无时间轴） |

**最痛的一条**：派发返回只代表「收下了」，界面无法区分「在跑」和「跑完了」。这不是视觉问题，
是 [`R-v1`](./route.md) 缺终态在界面上的投影。

## U-v1 · 结果卡 + 通知

| 工作项 | 做到什么 | 验收 |
|---|---|---|
| 结果卡 | 显示 `summary` + 证据（命令 / 退出码 / 改了哪些文件）+ 工件引用 | 一张卡能回答「它到底干了什么」 |
| 完成通知 | 面板卡片 + 系统通知；手机走 `dsh-task-notifier` 桥 | 长任务不需要盯面板 |
| 失败面 | 失败 / 取消 / 超时三种终态各自的文案与后续动作（重试 / 换机器） | 不出现「只显示 undefined」 |

**文案硬规则**（沿用 `AGENTS.md` 硬约束 1）：探测失败不能看起来像否定事实。
`ENOENT`（没装）≠ 超时（没应答）≠ 离线（没收到）—— 三者必须视觉可分。

## U-v2 · `mesh demo`

自动选一台对端 → 派「报一下你的系统和负载」→ 面板出结果卡 → 按钮「再来一条」。
**零思考走完闭环，同时最快的回归测试。**

**验收**：装完到首张结果卡 ≤5 分钟（含发现设备的时间）；无第二台机器时「看演示」可走假数据看完闭环。

---

## U-v3 · 驾驶舱

| 工作项 | 做到什么 |
|---|---|
| 横向时间线 | 复用 [`T-v1`](./trace.md) 的渲染：排队 → 在跑 → 完成，点开看证据 |
| 围观视图 | 对端 Web 已能投屏，进一步只读看「当前任务 + 最近几条输出」 |
| 空状态 | 没有设备 / 没有任务时给可执行的下一步，而不是空白表格 |

**验收**：每周围观次数可测（面板打开频次，本地统计 + opt-in）。

## 闸门

| 关系 | 说明 |
|---|---|
| **入** | U-v1 需要 [`R-v1`](./route.md) 的结果信封；U-v3 需要 [`T-v1`](./trace.md) |
| **出** | U 不闸别人 |

## 边界

- 不做独立客户端 / 公网 web（浏览器当看板与遥控器，不当节点）
- 不做视觉风格竞赛 —— 界面只承载上面三个数字
- 不在没有终态时假装有进度（宁可不显示进度条）
