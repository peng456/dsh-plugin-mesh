# P · 玩法 子路线图（组群 / 扇出 / 临时活动）

> 父文档：[`ROADMAP.md`](../../ROADMAP.md) §2 · v1 被 [`R-v1`](./route.md) 闸住（决策 D3）。
> **对外说「组群」，实现是扇出 + 读侧聚合 —— 不是群协议对象。**

**回答什么**：能不能一次让几台机器一起干，然后告诉我谁好了？

---

## 现状（v0）

**没有任何群概念**。`group` 只出现在面板按 `machine` 分组的展示逻辑里。
寻址单位是 `machine + agent`，派发是 1:1。

## P-v1 · 组群（实现：扇出 + 聚合）

```
mesh_run(group: ["mac", "win"], task: "各编译一个平台，产物发我")
        │
        ├─→ mac : t-1  ┐
        ├─→ win : t-2  ├─ N 张独立工单
        └─→ hos : t-3  ┘
                    ↓
        读侧按 groupId 收拢：
        「2/3 完成 · 1 失败」
```

**七条硬规格**

| # | 规格 | 为什么 |
|---|---|---|
| 1 | `groupId` 是**信封上的标签**，不是身份 | 不注册、不参与发现、不影响寻址 |
| 2 | **N 张独立工单**：独立 `taskId` / 状态 / 终态 / 取消 | **没有「群状态」** |
| 3 | 聚合**只在读侧** | 写侧不知道「群」存在 |
| 4 | **失败隔离** | 一张失败不影响其它，没有全有或全无 |
| 5 | **取消不是原子的** | 扇出 N 个 cancel，各自回「已停 / 太晚」，如实显示 |
| 6 | 协议增量**一个字段** `groupId?` | 老对端忽略即退化为一対一 |
| 7 | **依赖 R-v1** | 否则聚合数字是假的，只是把不确定放大 N 倍 |

**验收**：聚合数字与底层工单可逐一核对（100%）· 一张失败时其余照常收敛 · 老对端无感知。

## P-v2 · 临时活动

| 工作项 | 做到什么 |
|---|---|
| TTL | `groupId` + `expiresAt`；到期后聚合视图折叠成归档 |
| 工单不删 | 活动是标签，工单是记录 —— 归档只影响视图 |
| 周期性 | 「每周一次」不是调度器，只是**换一个目标列表再扇出一次** |

**验收**：归档后原工单仍可查；过期不产生新工单。

---

## P-v3 · 真群协议（条件触发，不设日期）

**触发条件**（满足其一类 ≥3 次真实需求）：需要**共享上下文** / 需要**成员权限继承** /
需要**跨节点消息序**。

为什么门槛这么高：真群需要成员表 + 权限继承 + 消息序 + 加入/退出/迁移，
会把 `machine` 这个寻址单位扩成「集合」—— **动的是地基**。而实际需求 90% 是
「这几台一起干，然后告诉我谁好了」，扇出 + 聚合就够。

## 闸门

| 关系 | 说明 |
|---|---|
| **入** | P-v1 需要 [`R-v1`](./route.md) 的终态；P-v3 需要三类需求触发 |
| **出** | P 不闸别人 |

## 边界（防「群」变成万能词）

| 不是 | 原因 |
|---|---|
| 不是共享会话 | N 个对端各有自己的会话，**不共享上下文**（共享上下文 = 白板 / 工件，观察区） |
| 不是广播唤醒 | `noWake` 语义不变，扇出只是多派了几张单 |
| 不是投票 / 共识 | 那是编排，见 [`ROADMAP.md`](../../ROADMAP.md) §2「不做」 |
| 不是小游戏 | 玩具只在 `play/` 当一致性测试，不进 `lib/`、不进 `files` |

## 风险

| 风险 | 应对 |
|---|---|
| 有人把「组群」做成成员表 + 权限 | 上面的七条硬规格；真协议需满足触发条件 |
| 聚合数字被当成真进度 | 必须先有 R-v1；聚合只反映已知终态，未知段显式标注 |
