# 60 秒演示：拍摄脚本与清单

> 目标：一个从不认识这个插件的人，看完能说出「它让我把活丢给另一台电脑，跑完告诉我」。
> 静音可看（全靠字幕），60 秒以内，两分钟能录完。
>
> 线上先放的是示意动画 [`demo.html`](./demo.html)。这份文件是**拍真实版**用的：
> 真实版一上线就替换掉示意动画，转化率会比动画更高。

---

## 一、镜头表

| 时间 | 画面 | 字幕（同时也是旁白） |
|---|---|---|
| 0–6s | 两台机器并排（Mac + 台式机），各自的 DSH 侧栏 Mesh 页开着，两台互相出现在列表里 | 两台电脑各装一次，它们自己找到彼此。 |
| 6–16s | 手机（或笔记本）上的 DSH 会话，输入 `@Studio 跑一遍测试，失败的用例发我`，点发送 | 你在手机上说要什么，派给那台台式机。 |
| 16–30s | 切到台式机：Mesh 设备页出现一条「收到任务」，会话自己开起来，终端在跑测试 | 它自己开一个会话去跑。你合上笔记本，它不受影响。 |
| 30–40s | 手机锁屏弹出通知：「Mesh · Studio：测试跑完了，2 个失败」 | 跑完了，它先通知你。 |
| 40–52s | 点开通知 →「任务」页 → 结果卡：摘要、命令、退出码、失败用例 | 点开是结果卡：摘要、命令、退出码、失败用例。 |
| 52–58s | 结果卡下方停 2 秒，画面叠一行安装命令 | `dsh plugin add dsh-plugin-mesh` |
| 58–60s | 尾卡：`合上笔记本，活还在跑` + 网址 | — |

**硬规则**

- 一条任务只讲一件事（跑测试），不要在同一支视频里演示第二个功能。
- 必须出现「通知」和「结果」，这是与"远程执行"的区别。
- 不解释组播、端口、tailnet —— 一个字都不要。

---

## 二、录制前准备

1. 两台机器都升级到同一个版本，都重启过 DSH，Mesh 页都能看到对方。
2. 在「任务」里清掉旧记录，避免截图里出现真实项目名 / 客户名 / 路径。
3. 把会话字号调大（至少 14px），深色模式更清晰（可选，但全片统一）。
4. 台式机提前 `pnpm install` 过、测试能在 4 分钟内跑完；录之前先跑一遍确认退出码是 1
   （demo 里要展示"有失败"这种真实结果，不要造假成全绿）。
5. 手机打开通知权限，锁屏通知可见。
6. 录屏 1080p / 30fps；用系统自带录屏即可。**不要录到 Dock、菜单栏里的私人信息**。

---

## 三、剪辑

- 全程 55–60 秒；超过 60 秒，砍前 6 秒的机器特写，直接从"发消息"开始。
- 字幕位置固定在底部，一条不超过 18 个汉字。
- 结尾 3 秒必须留安装命令 + 网址，方便截图传播。
- 导出 MP4（H.264），控制在 15 MB 以内；同时导一张 1280×720 的封面（结果卡那一帧）。
- 不要加背景音乐；如果要加，音量压到 -28 dB 以下 —— 这类视频多数在静音环境看。

---

## 四、发布位置（按顺序）

1. `docs/demo.html` 顶部嵌入真实视频（替换示意动画），README 第一屏链接过去；
2. npm 包的 README 同一条链接（README 会被原样展示在 npm 页面）；
3. 插件目录 / 社区群的帖子首条；
4. 视频号 / B 站 / 小红书：标题用「合上笔记本，活还在跑」而不是「Mesh 插件发布」。

---

## 五、验收

找 5 个用 DSH 但没用过这个插件的人，只给他们看这支视频，然后问：

1. 它是干什么的？
2. 你会拿它干什么？
3. 有什么地方没看懂？

三个人能答对前两问，就算过关；否则先改视频，不要改产品。
