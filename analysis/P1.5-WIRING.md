## 2. 接线实现（含锚点）

### 2.1 配置 schema（`lib/index.js:283-289`）

```js
usbEnabled: z.boolean().default(false),
usbAdbPath: z.string().default(""),
usbForwardBase: z.natural().min(1024).max(65000).default(46000),
usbPollMs: z.natural().min(1000).max(3600000).default(15000),
```
- 默认 `false`（opt-in）：不配 = 桌面/手机行为零变化。
- 真实 schemastery 校验（`E:\mesh\.tmp\schemaprobe\usb-config-check.mjs`）：
  `usbPollMs:5` / `usbForwardBase:80` / `usbEnabled:"yes"` 三种非法值 **3/3 被拒**。

### 2.2 `createUsbWiring()`（`lib/index.js:868`）

不把逻辑塞进 `applyUnsafe`，而是抽成可导出、可注入的函数（`createTransport` 可换 fake），
理由：这是真机验收的关键路径（端点登记/去重/脱敏/清理），必须能**离线单测**。

```js
createUsbWiring({ config, discovery, log, warn, createTransport })
// → { enabled, transport, createError, start, stop, status, diag }
```
- 只有 `config.usbEnabled === true` 才调用 `createTransport`（严格布尔，防御手写配置）。
- 传给模块的 options（`:868` 起）：
  - `adbPath`: `usbAdbPath.trim() || "adb"`；
  - `devicePort`: `MESH_DEFAULT_PORT`（45917，手机侧默认端口）；
  - `forwardBase`: `usbForwardBase` 钳制到 `[1024,65000]`；`pollMs`: `usbPollMs` 钳制到 `[1000,3600000]`；
  - `probeTimeoutMs`: `min(1200, requestTimeoutMs)`（只用于 health 探测，不是任务 HTTP 超时）；
  - `log`: 走插件 log（前缀 `usb:`）；`onError`: 记环形错误 + 一条 warn；
  - `onEndpoints`: **端点注册唯一入口**（见 2.3）。
- 任何一步都不抛：工厂抛错 → `createError` + diag 降级 `CREATE_FAILED`。

### 2.3 端点注册与去重合并（`lib/index.js:868` 的 `onEndpoints`）

```js
discovery.note(ep.record, ep.host || "127.0.0.1", {
  transport: "usb",
  channel: String(ep.key || `usb:${ep.serial}`),   // 端点身份 = usb:<serial>
  port: Number(ep.port) || 0,                       // 127.0.0.1:<forward 本地端口>
  rttMs: Number(ep.rttMs) || 0,
  probeIntervalMs,                                  // = max(1000, pingIntervalMs)
});
```
- `record` **原样**交给 `discovery.note()`：协议字段一个都不改（设计契约）。
- 通道 key 用 `usb:<serial>` → `discovery.#upsert` 按 **instanceId** 合并：
  同一台手机的 LAN 端点与 USB 端点落在同一个 peer 的 `endpoints` 下，
  **不会造第二个设备条目**（集成测试 §3 用真实 `MeshDiscovery` 断言）。
- `probeIntervalMs` 让 `endpointAlive` 的窗口跟随 USB 轮询节奏（不会"探着通却显示离线"）。
- 端点消失不需要额外 API：`pingKnownPeers()` 会像 LAN 端点一样保活探测，
  连续失败进冷却 → 设备离线；`stop()` 发布空列表后下一次 ping 就会把通道标失败。

### 2.4 生命周期（`lib/index.js:1193-1206`、`:1304-1322`）

- `applyUnsafe()` 里 discovery 就绪后创建 wiring；`usbEnabled=true` 时
  `ctx.effect(() => () => usbWiring.stop())` —— 卸载/热重载清定时器；模块只删自己建的 forward
  （用户手工 `adb forward` 的映射保留）；未启用时 log 一行 `USB 传输未启用（usbEnabled=false）`。
- 首轮轮询在 `startPeerServer(...).then(port => …)` 里、`// 主动发现 + 保活` 之前启动
  （HTTP 服务已就绪，日志顺序稳定）：可用时 log `USB 传输已启动：adb 1.0.41，可用设备 N 台，端点 M 个`；
  不可用时 warn 带 `reason`（`ENOENT` = 没装 adb，不是"没有手机"，符合 AGENTS.md 硬约束 1）。

## 3. `/mesh/v1/health` 的 `diag.usb`（脱敏）

`startPeerServer` 新增可选参数 `usbStatus`（`lib/index.js:2447`），health 路由把它塞进 diag
（`:2482`；异常分支 `:2492` 也保证形状）。示例（真机预期形状）：

```json
"diag": {
  "net": { "source": "os", "macsAvailable": false, "errors": [...] },
  "dshGo": { "isDshGo": true, "deviceModel": "Xiaomi 15 Ultra", "androidVersion": "15", ... },
  "sidecarTarget": { "os": "android", "arch": "arm64", "asset": "dsh-mesh-tsnet-android-arm64.gz", ... },
  "inboundPermissionPreset": "danger-full-access",
  "usb": {
    "enabled": true,
    "available": true,
    "reason": "",
    "adbVersion": "1.0.41",
    "started": true,
    "pollCount": 3,
    "devices": 1,
    "endpoints": 1,
    "errors": [{ "serial": "1441e87a", "phase": "probe", "code": "ETIMEDOUT" }]
  }
}
```
脱敏规则（health 是**未鉴权**接口）：
- 不含 `adbPath`（本机路径）、不含错误 `message`（可能带路径/令牌）；
- `errors` 只保留最近 5 条 `{serial, phase, code}`；
- `devices/endpoints` 是**计数**，不列 serial 清单；
- `usbStatus` 抛错时 diag 返回 `{reason:"DIAG_FAILED"}`，health 仍 200（集成测试 §6 断言）。

`diag({detail:true})`（只给诊断快照，不含 health）额外带 `devicePort/pollMs/forwards/skipped/endpointKeys`。

## 8. 风险 / 说明

1. **默认关闭**：不配置时行为与 P1 完全一致；`usbEnabled:true` 但没 adb 时只 warn
   （`available:false`），不影响 LAN/tsnet。
2. **配置在 `apply` 时读一次**：USB 传输随插件启动/重启生效（`usbPollMs/usbAdbPath` 改后需重启）；
   UI 上暂未接线开关键（client 不在写权限内）。
3. **devicePort 固定 45917**：手机侧 mesh 若把 `port` 改过，USB 探测会 `ECONNREFUSED`
   （diag 的 `errors[].code` 可见）；需要时后续加 `usbDevicePort` 配置。
4. **同一个 serial 的端点身份稳定**（`usb:<serial>`），进程重启后仍复用同一通道；
   `adb forward` 端口按 serial 稳定 hash，不会堆积孤儿映射。
5. **health diag 是未鉴权**：已经只放计数/错误码；serial 也不出现在 health（`detail:true` 才在诊断快照里给 skipped/endpointKeys）。
6. 真机端到端（关 Wi-Fi 用 USB 派发）仍待 Lead 验证；本地环境无 adb 设备，只能做到模块级 + 接线级（fake transport）验证。
